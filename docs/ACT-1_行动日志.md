## 目标

消除"行动判定后整节点正文重绘一遍"的重复渲染现象。行动结果文本不再混入正文流，正文只承载剧情节点文本。

## 扩充了什么（相对口令）

1. **固定"行动日志"折叠容器 `#v93-actlog`**（羊皮纸样式，与 v5 UI 一致），位于 `#options` 与 `#v68-status` 之间；头栏"✦ 行动日志（今日）"+ 折叠按钮，默认展开。
2. **条目按 `S.day` 分组**：头栏显示当前累计条数（如"行动日志·20条"），当天条目置顶，`第N日` 分组标题。
3. **条目上限 50 条滚动淘汰**（最旧优先），`window.__v93ActLog` 数组承载，纯前端 DOM 层，**不入存档结构，S 零改动**。
4. **骰子行分级样式**：`v93_actDice(roll,t,lvl)` 输出 `成功/失败/大成功/大失败（d100=X / 目标 Y）` 彩色条；结果行 `◆ 结果：…`（res）、风险行（risky）、提示行（hint）样式复用原 `actOut` 语义。
5. **面板内 `#act-out` 同步**：行动结果同时写入 `#act-out`（行动面板关闭后仍可回看最近结果），行动日志与面板并存。

## 为什么

- 原实现：每次行动后 `writeNext()` 整节点重绘——正文、地点、选项、全部 v9x 注入钩子重复执行一遍，玩家看到"刚读过的剧情又刷一遍"。
- 行动日志将**操作结果流水**（判定骰子/收益/失败后果）与**剧情节点文本**（小说正文）彻底分离：前者进日志，后者只在节点跳转时渲染。

## 边界与红线

- `writeNext` 本体零改动；`choose()` 判定路径零改动；存档结构零改动；`saveVersion=48` 不变。
- 与 I1-3 冒险手记区分：手记=剧情节点快照（localStorage 独立键），行动日志=操作结果流水（内存 DOM，50 条滚动），二者并存不互写。
