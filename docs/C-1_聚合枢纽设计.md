# C-1 主线聚合枢纽设计（超大型剧情八工程 · 工程 C）

> 批次：C-1 · 日期：2026-09-11 · 口令：《超大型剧情八工程（F/E/C/S/T/L/P/W）》
> 目标（CoG「分支狂但不裂主线」）：不同路径的玩家在关键节点**汇合**，正文因路径不同而不同，主线判定零改动。

## 一、设计原则

1. **聚合不分裂**：枢纽是"多入单出"——多条支线路径进入同一枢纽，枢纽出口回接原主线节点；主线判定（day/flag 触发）零改动。
2. **状态感知正文**：枢纽正文用 `node.ifFlag` 变体（v91_resolveText node 级，引擎零改动），不同路径（flag/立场/好感/锚数）看到不同引文与氛围句。
3. **插入方式**：选主线链路上的前驱节点，把其 `go` 改向枢纽，枢纽出口 `go` 回原目标节点。只改 1-2 处前驱出口，不删不改既有节点正文与选项语义。
4. **质量**：枢纽节点 deep 档（400-800 字），带 pace、进蓝图、涉设定同步账本。

## 三、正文结构（每个枢纽通用四段）

1. **路径引文**（ifFlag 变体，80-150 字）：点出玩家是从哪条路来的（"你沿着北上大军踏出的路……" vs "你从终局的硝烟里折返……"）。
2. **此时此地**（100-200 字）：当前区域的环境/时局白描（V66 五感）。
3. **回声与立场**（100-200 字）：回指玩家关键选择（E 批回响词/立场轴），不替玩家做决定。
4. **钩子**（60-100 字）：引出下一节点（保持原主线节点作为出口，只换引文语境）。

## 四、验收口径

- 10 个枢纽全部可达（入边 0 孤儿）、出口 0 死链
- 至少 2 个枢纽 bu 实测"两路径同枢纽正文不同"
- 主线 day 判定（purge 60/silver 120/seal 200/academy 250/orc 280）零改动
- elda ci 39 检查器全绿
