## 设计要点

1. **三幕结构**：m1=爆发（主触发后立即展开的场景），m2=波及（牵连身边人/组织），m3=抉择余波（记录 flag，为 F-2 代价节点铺路）
2. **暗线互串**（全部为既有设定回指，不新创）：金秤牛皮账（purge）↔ 七笔账姑娘（silver）↔ 南二铁牌+第七封（seal）↔ 费尔曼+金秤铜钱+沈砚（academy）↔ 狼营"账"字+羊皮密信+狼旗东进承天（orc）
3. **触发机制**：五主线节点 go 直达三幕链（选项语义等价增强，链末端回 world_continue）；余波节点由事件池 worldQueue 机制到城自动触发
4. **身份变体**：world_purge_m1 用 v91_resolveText 的 ifJob 变体（A-1 五键已落地），灵魂法师看到专属段落；其余节点通用正文
5. **新 flag**：purge_account / silver_seen / silver_account / seal_talisman / seal_south / seal_north / academy_witness / academy_vault / academy_shenyan / orc_letter / orc_ledger / orc_east（12 个，全部独立键，旧档兼容）
6. **新好感**：lu_zhao（码头姑娘，+2）、gu_qingwu（顾青梧，+3）

## 踩坑与修复（重要）

- **对象式 text 内三元表达式在页面加载早期求值**：`text:[...(S.job==="灵魂法师")?...:...]` 在节点对象构造时即求值，此时 S=null → TypeError → 整个 IIFE 中断 → 后续全部节点未注册（运行时 N 缺 20 节点）。修复：改为 v91_resolveText 的 raw 内嵌变体 `text:{default:[...], ifJob:{"灵魂法师":[...]}}`（渲染时求值，安全）。
- 治理词回潮：新文本引入"低声 ×8 / 隐约 ×1"推高全书计数（低声 31、隐约 31 > 30）→ 全部改写（"压低声音"/"认得出是个"），elda text guard 全绿。
