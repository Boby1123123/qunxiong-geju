## 设计要点

1. **双线互锁**：美第奇（身世）与金秤（守门）在石门汇合——"金秤家三代守门，美第奇家三代送信，守的是同一扇门"。heir 变体给出母亲线索（晨天故都姓秦的），为后续内容包预留
2. **四段式战斗**（ci c_tags 校验 combat tag + 受创段）：疤脸散兵战，受创具体（左臂/肩窝/肋下 + 血/青紫 + hp-8），越级不硬胜（失败=被捆，crit=反制）
3. **结局互锁**：ending_medici（守门）与 ending_war（战争）分流自 battle 三择；两者 go 汇入既有七锚结局链（ending_anchor_goldscale_1 / ending_anchor_war_1），零新结局注册风险
4. **回指闭环**：epilogue 回指 F-5 退伍兵代写家信（city_1）、蜜尔娜（city_3）、怀表（f5_escort）、老嬷嬷/顾青梧（F-3/F-4）——F 批次簇六批全部串成一个可回望的整体

## 踩坑与修复

1. **tags 数组 vs tag 字符串（新坑）**：检查器 c_tags 要求 `tags:["combat"]` / `tags:["ending:xxx"]` 数组格式（旧式 `tag:"combat"` 会被判"战斗节点缺 combat tag"；ending 节点要求 `ending:*` 前缀）——修复：battle 加 tags:["combat"]，三结局加 tags:["ending:medici"] 等
2. **结局 go 目标名不匹配**：M7 七锚结局实际节点名带 `_1/_2/_3` 后缀（ending_anchor_goldscale_1 而非 ending_anchor_goldscale）→ 死链 2 修复
3. **接线顺序**：blood_5 入口用"段内 options 首选项前"定位（吸取 F-5 hub 教训，不再用全局 find）
