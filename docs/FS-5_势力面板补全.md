## 一、改动内容

### 1.1 势力列表未知态（验收项①）

**现状问题**：势力列表 11 张卡直接显示全部势力全名 + 完整描述 + 完整路径卡，玩家开局即全知，缺乏"情报未知"的真实感。

**改动**（`v35_renderFactionTab` factions 卡片渲染处）：
- `known = isJoined || S.flags[V35_JOIN_PATHS[f.id].knownFlag]` —— 已加入或已获得 knownFlag 才显示真名
- 未知时：名称显示"？？？"；描述显示固定传闻文案"城里的传闻含糊不清，只说那批人行事隐秘，寻常人连他们的名号都打听不到。"；盟友/敌对行显示"传闻：尚未探明其立场"
- 已知（或已加入）时：保持原全名/描述/盟友敌对完整显示
- 按钮文案分流：未知势力显示"前往打听"（go 各自打听链首节点），已知未加入显示"申请加入"，已加入显示"退出势力"

**为什么**：
- 守望者/暗蚀会/东部王国等本就设计为"隐秘/需打听才知晓"的势力，直接全名暴露破坏世界沉浸
- 与 FS-3 加入路径机制（knownFlag）天然衔接——打听即点亮
- 纯展示层改动，零判定/零存档语义影响

**如何验证**：bu 实测新档开局打开势力列表——光明教会/暗蚀会（开局 known）显示真名，守望者/东部王国/北境等显示？？？+传闻+前往打听；打听后点亮真名。

### 1.2 总览"专属能力"显示（验收项②）

**现状问题**：V35_FACTIONS 各势力 `skills` 数组（如守望者 `["soul_sight","soul_mind_read"]`）只存在于数据层，面板无任何展示，玩家加入后不知道势力给了什么专属能力。

**改动**：overview（总览）"已完成任务"行下新增"专属能力"行——`myFaction.skills.map(sk=>V35_SKILLS[sk]?V35_SKILLS[sk].name:sk).join(' / ')`；skills 为空数组时不显示该行（兼容无技能势力）。

**为什么**：让"加入势力有专属能力"从隐藏数据变成可见收益，增强加入正反馈。

**如何验证**：bu 实测加入守望者后总览显示"专属能力：soul_sight / soul_mind_read"。
