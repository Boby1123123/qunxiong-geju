# G-CI1 死代码检测器性能优化（工程链）

> 批次：G-CI1 ｜ 日期：2026-09-10 ｜ 类型：工程链（无运行时改动）｜ 状态：已实施

## 一、问题

`elda ci` 的死代码检测（c_dead.py）耗时随 game.html 规模增长显著退化：6.4s（G-N1）→ 6.7s → 7.64s（G-N3），逼近慢检查器阈值 8s；总耗时一度 27.87s。根因是**三重 O(文件大小×条目数) 的逐项全文件扫描**：

1. **孤岛节点主循环**：4637 节点 × 4 次 `html.count(...)`（双/单引号 × 节点定义/字符串引用）= **~18,548 次全文件扫描 × 8.5MB ≈ 158GB 字符串扫描**；
2. **无调用函数**：每函数名一次 `html.count(name)` 子串计数（数百函数 × 8.5MB）；
3. **未用 S 字段**：每键一次 `html.count('S.'+k)`（数百键 × 8.5MB）。

## 二、优化方案（保持检测语义一致）

全部改为**一次正则 + Counter 统计**（O(文件大小)）：

| 检查项 | 优化前 | 优化后 |
|---|---|---|
| 孤岛节点引用计数 | 每节点 `count('"id"')+count("'id'")+count('N["id"]')+count("N['id']")` | `re.findall(r'"([\w$]*)"')` + `N\["..."\]` 两次扫描建 Counter，O(1) 查询 |
| 无调用函数 | 每名 `count(name)` | 一次标识符 token Counter（token 语义：定义处+调用处均计入，判定 `n_total<=ndef` 等价且抗词根误报如 run/running） |
| 未用 S 字段 | 每键 `count('S.'+k)` | 一次 `\bS\.([\w$]*)` Counter |

## 三、效果实测（清缓存真实耗时）

- 死代码检测：**7.64s → 1.52s（5 倍提速）**
- elda ci 总耗时：**27.87s → 16.35s**（38 检查器全绿，性能预算门 6 项 PASS，门禁「全部通过（可发布）」）
- 输出一致性：孤岛节点=0、未用 S 字段=0、无调用函数候选清单数量级不变（候选清单 ok 恒 True 不阻断，语义不降级）

## 四、阈值调整

优化后按真实基线收紧 `full_seconds_max` 30s → 24s（16.35s 基线 + 机器波动余量，保留门禁意义）；c_speed THRESHOLD 8s 保持（死代码 1.52s 远低于）。
