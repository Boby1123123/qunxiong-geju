## 三、本工程事故记录（重要，防再犯）

1. **分片覆盖丢失（重灾，已修复+根治）**
   - 现象：第二次跑 _v62_build_chunks.py 时，world 片从 12 节点覆盖为 14（v64b 新节点），旧 12 节点定义丢失；第三次构建又覆盖为 12，新 14 丢失。
   - 根因：构建脚本对片文件**覆盖写**，只提取主文件中该前缀的定义；分两次注入节点 + 中间构建 → 后一次提取不到先移走的节点 → 覆盖丢节点。
   - 修复：① _v62_build_chunks.py 增加 `extract_chunk_nodes()` + 合并逻辑（写片前读旧片、按 id 去重、主文件新提取优先，`[MERGE]` 日志）；② _v64b_restore_all.py 从内容脚本恢复全部 26 节点定义回主文件 → 单次构建全量移入（片 26 节点，合并验证 `[MERGE] world 片合并旧节点 12 个（总 26）`）。
   - **规范**：每次分片构建前，主文件必须包含该前缀的**全部**节点定义；新增节点走"内容脚本注入主文件 → 构建移入片"，禁直接改片文件。

2. **引擎被备份还原连带丢失（中）**
   - 现象：恢复节点时从 backup\game_v641_before.html 整体还原主文件，而该备份在 v64b 引擎注入**之前** → 引擎补丁（五变体/游说/按钮）全部丢失，elda full 仍绿（c_world 不查 v64b 内容）。
   - 修复：重跑 _v64b_engine.py（幂等 marker 检测自动跳过已注入）。仿真从"w64_warResult 未定义"转 PASS 确认恢复。
   - **规范**：任何"从备份还原"操作必须核对备份时间点；还原后立即跑对应版本的全部注入脚本（幂等）再验证。

3. **仿真环境缺 DOM stub（轻）**
   - sim sandbox 缺少 window.addEventListener / document.createElement 等 → script 执行中断导致后续函数未定义（误判注入失败）。补全 DOM stub 后 script[2] 全量加载（v22-v28 系统日志），诊断从"函数未定义"转为真实断言。
