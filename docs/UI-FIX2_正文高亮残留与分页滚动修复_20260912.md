# UI-FIX2 · 正文专名高亮残留乱码 / 继续阅读不自动滚动 / 世界书常驻刷屏 修复

> 批次：UI-FIX2_20260912 ｜ 日期：2026-09-12 ｜ 提交：见 git log
> 前置：UI-FIX（顶栏溢出 + 主界面面板 z-index）已上线（commit b05b824）

## 一、用户反馈

1. 每次选择完都会显示"九域格局 / 光明神系"两行设定（正文中出现 `艾尔达九域格局'>大陆九域并立…`、`九域格局'>大陆诸神曾于…` 的乱码残留），且每次推进剧情都重复出现。
2. 点击"继续阅读…"加载新页后，画面停留在原位置，需要手动下滑才看得到新文本。

## 二、根因（均已实测复现）

### 1. `XX'>` 乱码 —— v92_highlightNames 顺序替换破坏 HTML

- 正文渲染链路：`writeNext` → `v92_lorebook`（世界书常驻注入，constant 条目排最前）→ `writePar` → `rich(p)` → `v92_highlightNames(d)`（script_03.js:4350，A-N3 专名高亮）。
- 高亮按专名表（LOREBOOK.triggers，如「大陆」「九域」「北境」…）**逐词顺序 replace**。后处理的词会命中**前面已生成 `<span title='…'>` 的属性文本**（如 `title='九域格局'` 含「九域」），把属性值再次替换成 span，HTML 结构被破坏，浏览器把断裂片段渲染为可见的 `九域格局'>` 乱码。
- 复现：bu 页面构造「艾尔达大陆九域并立…」文本 → `v92_hlInit + v92_highlightNames` → innerHTML 出现 `title="&lt;span class=" v92-name'="">` 断裂结构。

### 2. 继续阅读不自动滚动

- `RenderBatch.flush()`（script_04.js:8207）已有 `el.scrollTop = el.scrollHeight`，但 `v45_renderPage`（script_03.js:3264）渲染新页后**没有再滚动**；后续渐显动画/后置渲染完成时滚动位置已滞后，实测分页第 1/2 页 `scrollTop` 均落后 `maxScroll` 约 59px（首测），用户需要手动下滑。

### 3. 每次推进都重复显示"九域格局 / 光明神系"

- `v92_lorebook`（script_03.js:3731）对 constant 条目**每节点无条件注入**（前置最多 3 条），无任何会话级去重 → 每个节点/每次选择后都重复刷屏。

## 三、修复（src/script_03.js，4 处）

1. **v92_hlInit**：构建单次联合正则 `window.v92_hlRe`（专名按长名优先 join `|`，全部转义）。
2. **v92_highlightNames**：改为**单次正则替换**（回调查 `v92_hlDesc` 生成 span），同一文本节点只替换一轮，title 属性文本不再被二次处理；`re.lastIndex=0` 复位。
3. **v92_lorebook**：constant 条目**会话级去重**（`window.__loreShown` 记录 entry.id，首次注入后本会话不再重复；不写存档；开关 `S.settings.lorebook` 关闭时零注入）。
4. **v45_renderPage**：渲染新页后追加滚动兜底（`requestAnimationFrame` 立即 + `setTimeout 450ms` 覆盖渐显动画/后置渲染），修复"继续阅读后需手动下滑"。

> 踩坑记录：修复 1/2 落地时，注释中误含未配对单引号（`/'/g`、`title='…'` 等），触发 eldacheck/jsscan 的 strip_equal 词法剥离（把其后全部代码当字符串剥空），导致「引用健康审计」误报 `v92_ambCSS 无声明`。已去掉注释/代码中的危险单引号并回退多余 title 转义，jsscan 写识别恢复。
