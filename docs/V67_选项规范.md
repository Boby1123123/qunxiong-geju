# V67 选项规范（Option Design Specification）

> 依据：黑曜石 GDC《对话选项设计原则》、Questas《UX of Choice》、Twine 分支设计。
> 适用范围：v67 起全部新增/修订节点的选项设计；存量节点不批量改，随内容迭代逐步对齐。

## 一、选项存在标准（黑曜石原则）

每个选项至少承担以下 **七种职责之一**，否则砍掉：

| 职责 | 说明 | 示例 |
|---|---|---|
| 推进 | 把剧情带向新节点 | “继续往南”“跟着他走” |
| 情报 | 获取新信息 | “问军官更多关于第一印的事” |
| 表达 | 传达玩家性格/立场（进双轴、名声、因果） | “把干饼分给他一半” |
| 关系 | 改变与 NPC/势力的关系 | “替他包扎伤口” |
| 代价 | 用资源/时间/风险换收益 | “花 20 金买情报” |
| 解锁 | 打开隐藏路径/条件内容 | “出示教廷信物” |
| 系统能力 | 调用职业/技能/流派能力 | “用元素魔法探测” |

审查方法：把选项文字盖住后续正文，若按钮本身无法独立理解其后果 → 重写（StoryFlow 测试法）。

## 二、数量与密度

- 单节点选项 **2–4 个**（含安全出口）；≥5 个需说明理由。
- 若选项可合并（同类推进），合并后再加差异化（情报/代价/表达）。
- 长正文（>250 词）至少补 1 个“观察/内心”类选项（v66_obs_* 已建）。

## 三、安全出口（Twine 防死路）

- 每个**非结局、非 auto** 节点必须有 1 个“返回/离开/稍后再议”语义选项。
- 结局节点（ending/death）例外，但必须由 writeNext 兜底（不卡死）。
- 详见 `v67_安全出口审计.md`（2095 个全前进候选，P2 逐批补）。

## 四、锁定态与反馈（v67 已落地）

| 状态 | 表现 | 实现 |
|---|---|---|
| 可点击 | 正常 | `.opt` |
| 条件不足 | 灰化 + disabled + title“条件不足” | `o.req()` 失败 → `.opt-locked` |
| 点击后 | 选中项金色描边高亮 800ms，其余立即灰化禁用 | `v67_uiFeedback` |
| 连点防护 | 点击后 `__v67Busy` 置锁，同帧二次点击无效 | `choose` 入口锁 + 5s 看门狗 |
| 分页/auto 节点 | 立即解锁（无选项场景） | `writeNext` 分页/auto 路径 busyClear |
| 判定成功率 | `（技能 · 成功率约 N%）` 标签；<10% 加“凶险” | `o.check` 渲染 |

## 五、文本规范

- 选项前缀 `◆`，短句（≤14 字），动词开头。
- 禁止 AI 高频词（微微/陡然/顿时/欲言又止/五味杂陈/眸光微沉/不是X而是Y）。
- 选项后果暗示（情报/代价/关系）写在 `o.note`（`（…）`），不写进 `o.t`。
- 中文引号，文风遵循 doubao-human-signal。

## 六、扩展位（P1/P2）

- 键盘 1–9 数字快捷选择。
- 选项 hover 预览后果（弱提示）。
- 选项频率统计（哪些选项从未被选 → 内容优化信号）。
