# QA_v40_检验报告

## 一、本轮目标
对 v39 完成态（2598节点）进行故事连续性/完整性深度修复，核心是**清理 v38 自动生成的占位节点**与**修复历史遗留的节点覆盖 bug**，让整体故事像"一本长篇完本小说"一样连续、有逻辑、完整。

## 二、重大发现与根因分析

### 发现1：125个节点存在重复定义（最严重）
- 游戏中有**两套格式**的节点定义：
  - 后期精修版：`N["id"] = { place, where, text:[...], options:[...] }`（对象格式，v34+ 精修，含完整叙事与动态逻辑）
  - 早期/占位版：`N["id"]=function(){return{...}}`（函数格式）
- **125个节点同时存在两种定义**，且函数格式定义位于文件后部 → JS 加载时**后定义覆盖前定义** → 精修版被占位版/早期版覆盖 → 玩家看到"你来到了一个新的地方"等占位文本，而非精心撰写的叙事。
- 根因：v38 死链清理工具 `_check_dead_links.py` 的正则 `N\["id"\]\s*=\s*function` **不识别 `= {` 对象格式**，把精修版节点误判为"不存在"，自动生成占位节点并后置插入 → 覆盖。

### 发现2：askConfirm 函数缺失（入口阻断）
- `askConfirm`（确认对话框）被3处调用（newGame 建号、结局重开、存档恢复）但**无定义** → 建号流程直接报错无法开始。
- 疑似 v34 UI 重构时误删。

### 发现3：占位节点总量
- 含"此节点为v38自动生成的占位节点"标记的节点：**369个**（重名125 + 纯占位244）。
- 这些节点文本为"你来到了一个新的地方"+占位说明，是故事断层的主因。

## 三、修复与改进内容

### 修复1：节点去重（125个）
- 删除125个重名节点的函数格式定义，**恢复全部精修版**（如 fc_jiaohui_entry「交汇城很大…」、fc_tavern「跛脚酒桶…」、north_tavern「旅鸮酒馆…」、world_continue 动态逻辑等）。
- 所有重名节点均确认保留精修版（0个无精修版）。

### 修复2：askConfirm 补充
- 新增 `askConfirm(msg)` 实现（window.confirm 包装，同步返回布尔），建号/重开/读档流程恢复。

### 修复3：死链检查工具升级
- `_check_dead_links.py` 正则升级为同时识别 `=function` 与 `= {` 两种格式，消除误报根源。
