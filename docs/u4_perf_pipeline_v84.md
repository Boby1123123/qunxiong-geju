# U4 · 性能管线（B2 首屏基线 + story DOM 归档压测）

> 批次：U4 | 日期：2026-09-09 | 依据：U1-U9 口令 B2 项
> 本批以测量与记录为主，**零代码改动**（归档机制 v74 已于此前批次落地，本批做实测验证与基线固化）

## 一、首屏性能基线（bu 浏览器平面，file://，Windows Chrome）

| 指标 | 分片版（index.html，推荐入口） | 单文件版（game.html） | 说明 |
|---|---|---|---|
| 传输字节 | 3,394,795B（3.39MB） | 6,026,510B（6.03MB） | 分片省 44% |
| DOMContentLoaded | **101ms** | **324ms** | 分片快 3.2 倍 |
| DOMInteractive | 100ms | 323ms | 同趋势 |
| LoadEventEnd | **267ms** | **610ms** | 分片快 2.3 倍 |
| 长任务 | 0（max 0ms） | 0（max 0ms） | 两版均无阻塞主线程长任务 |
| 游戏启动 | S=object，正文动态渲染，console 0 错误 | 同左 | 双版正常 |

**结论**：分片版为推荐入口（首屏快、传输省）；单文件版在 file:// 双击场景下 324ms DCL / 610ms Load 亦可接受（无长任务，无卡顿）。

## 二、story DOM 归档压测（长会话 500KB 级）

机制回顾（v74，script_04.js:8159）：段落 >400 **或** 文本 >500,000 字符 → 旧段落折叠进可回看的 `<details class="v74-archive">`，正文区保持 ≤200 段。

**实测（单文件版，浏览器真实环境）**：

| 阶段 | 数据 |
|---|---|
| 追加 800 段（总文本 ~475KB） | appendMs=1ms（无卡顿） |
| 归档触发 | 段落 800>400 阈值 → v74_archiveIfNeeded 生效 |
| 归档后正文区 | **201 子元素**（200 保留 + 1 归档块） |
| 归档内容 | **600 段**移入 .v74-archive-body（summary："↑ 回顾历史（600 段）"） |
| 回看验证 | details.open=true → 归档正文 355,690 字符完整可读 |
| 全局 DOM 规模 | 归档后 1,225 节点（受控，不随会话无限增长） |

**性能前后对比**：长会话文本 475KB 时，正文 DOM 从 800+ 段降至 201 段（降 75%）；后续渲染、滚动、重绘均不受历史内容拖累。

## 三、超大型目标（5 万节点级）支撑论证

1. **首屏不劣化**：分片机制（ChunkLoader 按需注入）下，5 万节点 = 更多 chunk 文件（当前 14 片 1,806 节点 ≈ 129 节点/片，可重组为大片），首屏仍只加载引擎 + 索引 + 当前区域节点，DCL 保持在 100ms 级
2. **长会话不劣化**：v74 归档机制将 story DOM 锁定在 ≤201 段（约 500KB 上限），5 万节点级游玩的长会话 DOM 规模与本测一致
3. **存储可扩展**：U3 已实测 IndexedDB 超限迁移（6.3MB 存档自动迁移、可回读）——5 万节点下存档天然走大容量存储
4. **内容注入可扩展**：NODE_MAP（3,268 项）作为分片加载索引，新增分片只需登记 NODE_MAP + 数据文件，引擎零改动（U6 内容工具将固化此流程）
