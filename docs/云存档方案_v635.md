# 云存档方案（v63.5 预留，未启用）

> 状态：**设计已定、槽位已留、未实现**。用户提供 Supabase URL + anonKey 后启用。

## 一、现状（已落地）

StorageKit 三层存储已实现（game.html v42 技术层）：

| 层 | 实现 | 说明 |
|---|---|---|
| localStorage | `saveToLS` / `readFromLS` | 主存储，LZString 压缩（`lz1:` 前缀 + sniffRaw 嗅探），键 `elda-qunxiong-v3-save` / `elda-save-slot-*` |
| IndexedDB | `saveToIDB` / `readFromIDB` / `loadIDB` | 异步灾备副本，库 `elda-saves` / 表 `saves`，保存时自动双写 |
| 导出/导入 | `exportJSON` / `importJSON` | Blob 下载 JSON + FileReader 导入（支持明文/lz1 双格式） |

## 二、云层接入点（v63_cloud 槽位，game.html 已留注释）

```js
// 接入点：StorageKit 之后
window.v63_cloud = {
  save: function(slot, data){ /* POST {slot, data} 到 Supabase */ },
  load: function(slot, cb){ /* GET 单槽位 */ },
  list: function(cb){ /* GET 全部槽位 */ }
};
// 配置
window.v63_cloudConfig = { url: "https://xxx.supabase.co", anonKey: "..." };
```

**行为契约（硬约束）**：
1. 云为**第三副本**：save 成功后仍写 LS + IDB（云失败不回滚本地）
2. load 失败回退 LS（云不可用不阻塞读档）
3. 不改变 StorageKit 既有 API（save/load/deleteSlot/exportJSON/importJSON 签名不动）
4. 存档内容不因云层改变格式（仍为明文 JSON 或 lz1 压缩串）

## 三、Supabase 表设计（建议）

```sql
create table saves (
  player_id text primary key,   -- 玩家标识（可选匿名 uuid）
  slot text,                    -- slot1..slotN
  data text,                    -- 存档串（lz1 压缩）
  updated_at timestamptz default now(),
  unique (player_id, slot)
);
```

## 四、启用步骤（下版）

1. 用户提供 Supabase 项目 URL + anonKey（连接器 `supabase-platform` 已具备）
2. 配置写入 `window.v63_cloudConfig`（或 localStorage 键 `elda-cloud-config`）
3. 实现 v63_cloud 三函数（fetch 到 Supabase REST/PostgREST）
4. 设置面板加"云存档"三按钮（上传/下载/列表），按行为契约接入
5. elda serve 下本地开发验证；file:// 下云层不可用（CORS/无网络时自动回退 LS）

## 五、风险

- file:// 下 fetch Supabase 受 CORS 限制 → 云功能仅在 http://（elda serve）或部署后可用
- anonKey 是公开只读密钥，仅做行级安全（RLS）保护，不含服务端密钥
- 不引入任何外部 JS 库（全部 fetch 原生实现）
