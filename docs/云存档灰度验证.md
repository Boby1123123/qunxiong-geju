## 二、配置云端

1. 游戏内：设置 → 云存档 → 「⚙ 配置云端」
2. 依次输入：Supabase 项目 URL（如 `https://xxxx.supabase.co`）→ anonKey
3. 配置存入 localStorage 键 `elda-cloud-config`（不上传任何密钥）
4. 状态栏变为「已配置」，三个云按钮可用

### Supabase 侧准备（一次性）
```sql
create table if not exists saves (
  player_id text not null,
  slot text not null,
  data text not null,
  updated_at timestamptz not null default now(),
  primary key (player_id, slot)
);
alter table saves enable row level security;
-- 单机/自托管场景可先放开（正式多用户再收紧为 auth.uid()）：
create policy "owner access" on saves for all using (player_id = auth.uid());
-- 或简单模式：应用层 player_id 已派生，可先 allow all（配合仅本机使用）
```

## 三、三按钮功能

| 按钮 | 行为 |
|---|---|
| ☁ 上传存档 | 先弹「最近保存时间」确认 → POST upsert（云为第三副本，本地保留） |
| ☁ 下载存档 | 按时间戳裁决：云端新→先备份本地为冲突副本再覆盖；本地新→提示建议先上传 |
| ☁ 云端列表 | 显示该 player_id 全部槽位 + 更新时间，可逐槽位下载 |
| ⚙ 配置云端 | 设置/修改 Supabase URL + anonKey |

## 四、冲突裁决规则（时间戳）

- `云端 updated_at > 本地 saveTime` → 远端更新：下载覆盖前把本地备份为 `elda-save-slot-<slot>--conflict-<ts>`
- `本地 saveTime > 云端 updated_at` → 本地更新：提示「建议先上传」，确认后仍可覆盖
- 无法比较（无 updated_at / 无 saveTime）→ 走远端更新分支（默认下载 + 本地备份）

## 五、本地完整验证流程（无真实 Supabase 也可测）

serve 页面控制台可注入 mock（验证三函数与裁决逻辑，方法见 docs\CS线_云存档灰度.md §三）：
1. 注入 mock fetch + 配置 elda-cloud-config
2. `v63_cloud.save('slot1', data, cb)` → 云端 store 出现该槽位
3. 删除本地存档键 → `v63_cloud.load('slot1', cb)` → 数据恢复（含 updatedAt）
4. 改云端 updated_at 为未来 → v63_download → 确认文案含「本地旧档已备份为冲突副本」
5. 改本地 saveTime 为未来 → v63_download → 确认文案含「比云端……更新」
