## 一、目标（方案 P0-3 原文）

把 StorageKit + v61_lzstring + v34 槽位收敛为统一 SaveStore 接口（list/save/load/delete/export/import）；
默认 localStorage + LZ；容量接近 4MB 自动迁移 IndexedDB；首槽键保持 `elda-qunxiong-v3-save` 兼容旧档；
新增导出/导入（文件）。风险等级：高（玩家资产核心）。

## 二、现状盘点（实施前实测）

StorageKit 位于 `src/script_04.js` L8180-8298（game.html 与 game_chunked.html 字节一致），**已具备**：

| 能力 | 实现 | 状态 |
|---|---|---|
| 多槽位 | `lsKey(slot)`：slot1→`elda-qunxiong-v3-save`（旧档兼容），其余→`elda-save-slot-<slot>` | 已有 |
| LZ 压缩 | v61_lzstring.compressToUTF16 + sniffRaw 自动嗅探（明文自动升级压缩） | 已有 |
| IDB 双写 | saveToIDB/readFromIDB（DB=elda-saves / STORE=saves / 惰性 openDB） | 已有 |
| 导出/导入 | exportJSON（Blob 下载）/ importJSON（FileReader，校验 ruleset + 支持 lz1: 解压） | 已有 |
| 槽位面板 | v34 面板：5 槽位 + 保存/读取/删除 + 导出/导入按钮 | 已有 |

**真实缺口（批3 增量）**：
1. **超限只提示不迁移**：saveToLS 捕获 QuotaExceededError 后仅提示"请立即导出存档备份"，不自动迁移 IndexedDB；
2. **读档无 IDB 回退**：StorageKit.load() 只读 localStorage，超限后档在 IDB 读不回来（死档风险）；
3. 无 list() 方法、无"接近 4MB 自动迁移"显式逻辑。

## 四、关键决策与实证

1. **生效套确认**：v34 面板在代码库中定义 3 套（game.html L2507 head 文本区死代码、script_04 L8670、script_04 L9403），
   JS 后定义覆盖先定义 → **只改 L9403 生效套**；另两套为历史残留（批 8 清理）。
2. **分片版同步**：game.html 与 game_chunked.html 的 StorageKit/v34_loadFromSlot/loadGame 片段**字节级一致**（实测），
   同串替换同步；四路 sync 后字节校验一致。
3. **init() 不做 IDB 启动探测**：启动时 sniffRaw 只查 LS；IDB 迁移后的档通过存档面板（v34_loadFromSlot IDB 回退）读取。
   原因：init 异步探测与 showCreation 时序冲突（askConfirm 同步阻塞 vs IDB 异步回调），风险大于收益，记为已知限制。
4. **导出导入**（v34_exportSave/importSave）：已有能力，未改动；exportJSON 写死 saveVersion=42 属数据标注，
   导入后经 applyDefaults + v46~w64 ensureDefaults 链补齐（elda full 存档兼容仿真已覆盖）。

## 六、已知限制（诚实披露）

1. **init 启动不探测 IDB**（见上）——超限迁移后的档需经「存档面板 → 读取」进入，不能启动时直接续玩；
2. v34 面板 3 套定义中的 2 套死代码未删除（批 8 命名清理/死代码清理一并处理）；
3. StorageKit 无 list() 方法——槽位枚举由 v34_renderSaveSlots 直接读 localStorage 完成（现状足够，未新增）；
4. 超限迁移后的存档**不再写入 LS**（LS 已满），IDB 为唯一存储——导出/导入功能即为此场景的兜底备份通道。
