## E6-① · elda restore —— 快照恢复命令化

- **扩了什么**：新增 `elda restore` 子命令族：
  - `elda restore --list`：列出 backup\ 全部快照（时间/大小/原因）
  - `elda restore --name <snap_x.zip>` / `--latest`：解压恢复指定快照
  - `--dry-run`：只预览将覆盖的文件清单，不写入
  - `--no-backup`：恢复前跳过"当前状态备份"（默认先备份为 `backup\pre_restore_*.zip`，可回退）
- **为什么**：回滚此前只能手工解压 zip；恢复是破坏性操作，必须"恢复前先备份当前 + 可预览 + 防御路径穿越"。
- **如何验证**：`elda restore --list` 正确列出 3 份快照（E6 / pre-commit / E1-mount-test）；`--dry-run` 预览不写入；zip 成员路径合法性检查（拒绝 `..`/绝对路径）已实现。

## E6-② · elda test branches —— 支线闭环检测

- **扩了什么**：`elda test branches`（并入 `elda test all`）——扫描全部 `tag:"branch"` 节点（288 个），按 id 字母前缀分组（238 组，≥2 节点算支线），校验：
  - **FAIL 条件（真缺陷）**：组内节点缺 text / text 空；组内节点无出边（支线中断）
  - **WARN 条件（合法结构）**：无静态入边（事件/状态机动态进入）；组内无直接互链（经主线 hub 中转）
- **为什么**：支线是内容扩展主力（BD 四包 + 后续内容包都在加 tag:"branch"），此前无闭环回归，坏链只能靠人工发现。
- **踩坑修复（检查器两轮修正）**：
  1. 首版把"组内不可达/组内无边"当 FAIL → 误报 4 组（fsh_hlj_letter/fsh_seal/fsh_watcher/pol_math_book）。**实证**：这些支线是合法结构——fsh_hlj_letter1 出边 `go:"fsh_dream_gate"/"pol_hub"`（经主线中转），fsh_seal1 → `pol_hub`，fsh_watcher1 → `pol_third_party/pol_hub`，pol_math_book 两节点均指向外部。改判为 WARN（"依赖外部中转"）。
  2. pol_math_book 组误判源于 `N["pol_math_book"]` 与 `N["pol_math_book2"]` 前缀相同（正分组），但组内无边是"外部中转"而非断裂。
- **如何验证**：`elda test branches` → **PASS（238 组，288 节点，全部有文本/出边/闭环）**；WARN 均为动态进入/外部中转提示；`elda test all` 全绿。

## E6-③ · CI 自动生成发布页

- **扩了什么**：新增 `tools/elda/gen_release_page.py`（纯标准库）——解析 `docs/版本发布记录.md` 的 `## vXX（日期）` 段，生成 `docs/release.html`（游戏风版本卡片列表 + 在线游玩链接 + 自动时间戳）；ci.yml 在门禁全绿后自动运行并**提交回 main**（commit 信息含 `[skip ci]` 防 CI 循环），GitHub Pages 即刻更新发布页。
