- **扩了什么**：`elda release [--note X] [--push]` 四步流水线——门禁 `elda ci`（不绿禁止发版）→ 读 `version.json` bump（v91→v92）→ 扫描 docs 最近 8 个批次文档自动生成 Release Notes 追加 `docs/版本发布记录.md` → `git tag`（可选 `--push`）。
- **为什么**：发版环节此前手工程序多（版本号、Release Notes、tag 易漏/易错），固化后一键。
- **如何验证**：实测全流程通过；`version.json` 生成 v92、Notes 含 8 条批次、tag v92 已打；后因 tag 先于提交打出而重新指向 `b99b61d` 并推送。

## E3 · 全量回归（elda test）

- **扩了什么**：`elda test all|endings|events`——结局类节点（ending/epilogue/aftermath/v24_final/v36_ending/ngplus_true 前缀）全量校验"有文本（非空串/空数组）+ 有出边"+ 入边统计；事件池（EVENT_POOL_EXT）逐条校验 id 唯一 / cls ∈ {天灾,人祸,奇遇,商机} / day 1~9999 / text≥8 字。

- **如何验证**：`elda test all` → 结局校验 PASS（25 个全部有文本与出边；12 个无入边结局为状态机动态可达，WARN 不阻断）+ 事件校验 PASS（95 则全部结构合法）。
