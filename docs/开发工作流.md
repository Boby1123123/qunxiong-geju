# 群雄割据 · 开发工作流（三技能流水线）

> 本文件把《艾尔达大陆·群雄割据》的日常开发更新固化为标准流程。**任何内容/功能/修复改动都走这条流水线**，三技能各司其职，机器门禁双保险（本地 pre-commit + 云端 CI）。

## 流水线总览

```
① elda-content-author    写作：新节点/事件/支线按 schema 产出，V66 文风 + 治理词约束
② elda-story-guard       把关：写作前预检（人设/地名/时间线/势力立场）+ 写作后终检（账本/设定词/死链）
③ elda-ci-guard          验证：node --check → elda ci(21检查器) → smoke → 四路字节 → git 状态
④ 发布                   git push → GitHub Actions 云端门禁 → Pages 自动部署上线
```

## 标准操作步骤

### 1. 开工前
- 读 `skills/elda-ci-guard/references/pitfalls.md`（30 条已实证坑）与 `baselines.md`（基线对照）。
- 备份将改动文件到 `backup\<批次>_<日期>\`（如 `CM5_20260909`）。

### 2. 写内容（elda-content-author）
- 新节点 → `src\data_nodes\dn_*.js`；新事件 → `src\script_01.js` EVENT_POOL_EXT；新入口 → `src\script_02.js`。
- 脚手架：`python -X utf8 tools\elda\elda.py content new --type <main|branch|event|ending> --id <id> --vol <卷>`。
- 节点必带 `pace` 字段；变体用 `ifFlag/ifRelation`；涉及伏笔同步登记账本 `dn_causality.js`。

### 3. 把关（elda-story-guard）
- 写作前四问：人物 OOC？地名存在？时间线冲突？势力立场被扭曲？
- 写作后机器校验：`elda content causality`（账本核销 + 设定词覆盖率）+ `elda content chain`（死链）+ `elda text guard`（治理词/引号）。

### 4. 验证（elda-ci-guard）
```powershell
python -X utf8 skills\elda-ci-guard\scripts\ci_guard.py --quick   :: 快速门禁
python -X utf8 skills\elda-ci-guard\scripts\ci_guard.py --build   :: 完整构建链
```
- 全绿才允许提交；FAIL 立即停止、修复、重跑。

### 5. 发布（双保险门禁）
- **本地**：`.githooks\pre-commit` —— 提交涉及 src/tools/发布文件时自动跑 `--quick`，不绿阻止提交（`git commit --no-verify` 可绕过，不推荐）。
- **云端**：`.github\workflows\ci.yml` —— push 到 main 自动跑 `--build`，红灯即不可发布。
- 提交：`git add -A ; git commit -m "<批次>：<摘要>" ; git push`。
- 部署：GitHub Pages 自动重新部署（5-15 分钟），线上 https://boby1123123.github.io/qunxiong-geju/
