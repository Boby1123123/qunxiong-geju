## 二、对标项目逐个简评

### 2.1 Ink / Inky（inkle，4,935★）

Ink 是交互小说领域**分支收敛模型**的标杆。核心结构三层：knot（场景）→ stitch（场景内事件）→ weave（前向流，`*` 选项 + `-` gather 收束）。最精妙的是 stitch 可一次性消费后自动进入下一 stitch，以及 `->->` 隐式流，从根本上避免分支爆炸。运行时循环极简：`while(canContinue) Continue()` 吐文本 → `currentChoices` → `ChooseChoiceIndex(i)`。存档即 `state.ToJson()` 单一字符串——完整恢复调用栈+变量+访问计数。

**对本项目最有价值的三个模式**：①`state.ToJson()` 整体替换式存档（本项目单文件纯前端天然适配）；②`ObserveVariable()` 声明式 UI 同步（4601 节点手动刷 UI 必漏）；③行内 `#tag` 元数据通道（节点正文打 `#faction:merchant #combat`，运行时不显示，供 UI/统计/成就触发）。

**西幻代表**：《80 Days》（城市 hub 网络+环球叙事）、《Heaven's Vault》（考古知识模型，按发现顺序自适应叙事）、《Sorcery!》（手绘 3D 世界地图+法术词系统）、《Pendragon》（圆桌骑士招募+随机化棋盘）。

### 2.2 Ren'Py（6,809★）

视觉小说引擎，但其**rollback 回滚系统**是交互叙事领域最成熟的实现。每条可交互语句前自动打 checkpoint（快照全部可变对象引用），存入 `game.log` 环形缓冲；用户按回退即指针回拨、重新执行到该 checkpoint。提供 `block_rollback()`（阻断回退到此前）和 `fix_rollback()`（锁定已做决定不可反悔）两个原语处理"不可逆操作"。

**对本项目最有价值**：①rollback 环形缓冲 → 节点栈回退（限长 50，对死亡/背叛等不可逆事件调用 block_rollback）；②`persistent` 跨存档字典 → 结局图鉴（标题页展示"已见结局 3/25"）；③成就系统独立于存档。

### 2.3 ChoiceScript（Choice of Games，458★）

虽然 star 数不高，但它是 Choice of Games 整个商业产品线的引擎，**内容生产质检**是行业最强项。`quicktest` 系统性遍历每个 `#option` 做覆盖测试；`randomtest` 随机反复游玩并输出每行命中报告找死代码——CoG 出版门槛=两测必过。

**对本项目最有价值**：①quicktest/randomtest → 本项目发布前 CI 增加路径覆盖测试（静态遍历节点字典校验 goto 目标/flag 引用/不可达节点）；②成就与存档解耦（独立 localStorage key，重开不清空）；③属性屏独立场景（固定渲染函数吃同一份 vars 渲染种族/职业/阵营/关系总览）；④CoG 官方《7 Rules for Designing Great Stats》强调"不要全是技能，要加价值观/关系轴"——本项目 infl 九地影响力 + worldFame 四维名声已走在正确方向。

**西幻代表**：《Choice of the Dragon》（扮演龙）、《Choice of the Vampire》（90 万词，Stealth/Streetwise/Lore 技能+吸血鬼派系+狩猎者）、《Games of the Monarch's Eye》（Artisans/Merchants/Monarch 三阵营+禁术魔法）、《Vampire: The Masquerade》（True Faith/occult 宗教轴）。

### 2.4 Twine / SugarCube v2（269★）

Twine 生态最强大的故事格式。以 passage（段落）为原子单元，跳转即生成 moment（时刻快照）——记录"当前 passage + 全部 `$` 故事变量"。变量分三层：`$var`（故事变量，进历史）、`_var`（临时变量）、`setup.*`（不序列化的常量）。存档分四级：Save.slots（localStorage 槽位）、导出/导入 JSON、autosave、playthrough session（sessionStorage 防刷新丢失）。

**关键经验教训**：moment 只在"跳转到新 passage"时生成，同 passage 内点链接改变量后立刻存档，该变量改动**不会**进当前 moment——本项目若做回退必须修正此坑。

**对本项目最有价值**：三级持久化（命名槽位+导出导入+sessionStorage 防刷新）+ moment 快照的"只在节点切换时生成"经验。

### 2.5 Evennia（2,097★）

现代 Python MUD 框架，哲学是"不规定题材，只解决网络和基础架构"。核心是 **Typeclass 三段式对象模型**：Django proxy model 作为根 `ObjectDB`，派生出 `DefaultObject → DefaultCharacter / DefaultRoom / DefaultExit`。世界图是 Room-Exit-Room 有向图。Scripts 是可持久化、可定时、可重启后恢复的回调对象（支持 `GLOBAL_SCRIPTS` 跨房间存在）。

**对本项目最有价值**：①Typeclass 三段式 → 本项目节点按"九域 REGIONS → 区域对象 → 节点 → 出口/选项边"三级组织；②Scripts 全局回调 → 事件池引入"全局钩子脚本"（每 N 步扫描条件触发，如声望<阈值触发通缉）；③区域（Area）= 一组 Room 的集合，可整体加载/卸载 → 本项目节点按九域物理分区。

### 2.6 SillyTavern（33,204★）

LLM 前端王者，**World Info/Lorebook 世界书机制**是本项目设定词系统升级的直接对标。每个条目 = 关键词列表 + 正文 + 触发策略（constant 常驻/关键词命中/概率触发/递归展开）。命中后按"插入深度（depth）"插到上下文指定位置。支持正则关键词、AND/NOT 过滤器、包含组（同组多命中只插一条）、递归（词条 A 提到关键词 B 即连带激活 B）、定时效果（粘性/冷却/延迟）、token 预算。

**上下文分层模型**（SillyTavern/NovelAI/KoboldAI 共识）：Main Prompt（系统）→ 角色卡 → Lorebook（动态注入）→ Author's Note → 摘要 → 原始对话，每层职责清晰、token 预算显式。

**对本项目最有价值**：①设定词 20/20 从全量常驻升级为关键词触发注入（加 triggers[] + constant 标记 + recursive 链）；②记忆注入从"6 类触发"升级为"双层加权检索"（世界规则层 constant + 事件记忆层按 importance×recency 选 Top-K）；③上下文分层模板。

### 2.7 AI Dungeon / Latitude（闭源，SDK 61★）

AI Dungeon 的 **Memory Bank + 加权检索**是 LLM 叙事长期一致性的关键设计。Auto Summarization 自动把旧对话压缩成摘要；Memory Bank 把关键事实存为可检索条目，相关时动态插入上下文。2024 年后升级为 RAG 加权检索，**"世界规则"权重高于"历史事件"权重**——这是核心设计哲学。

Latitude World Engine（Voyage 平台）采用**"叙事层自由 + 规则层确定性"双层架构**：确定性状态层跟踪 health/inventory/currency/geography/relationships，LLM 在其上当"公正 DM"，不能篡改数值。

**对本项目最有价值**：①世界规则权重 > 历史事件权重的注入排序；②"叙事层自由 + 规则层确定性"——本项目 writeNext/choose 判定公式是确定性规则层，文本渲染是叙事层，架构已天然分层；③Auto Summarization → 因果账本的"未回收伏笔"字段天然就是摘要。

### 2.8 CoffeeMud（233★）

Java Diku 风格 MUD，**西幻数据结构的活化石级参考**。48 职业（7 大类）/10 玩家种族，技能/配方/任务/社交/派系全部数据驱动。OLC（Online Creation）允许在游戏内直接建区域。Area 目录组织房间文件。

**对本项目最有价值**：①种族特长/职业技能树/法术配方/阵营声望的数据类定义方式，可直接对照本项目"种族/职业/魔法/阵营"七维；②`areas/` 目录布局 → 节点按九域物理分区组织。

### 2.9 Quest 5（345★）/ QuestJS（91★）

面向对象世界模型——一切皆对象，挂在树里；room 有 exits（方向→另一 room）；物品/角色有 parent（所在容器）。对象属性即脚本+数据：`<enter>`/`<exit>` 脚本回调、`look` 描述、verb 定义。Quest 5.7 自带 500+ 单元测试，发布流程工程化程度最高。

**对本项目最有价值**：对象树 enter/exit 脚本回调 → 本项目节点数据加 `onEnter`/`onExit` 钩子字段（函数引用或事件名），由引擎分发，不引入继承树。

### 2.10 中文互动叙事平台（橙光/易次元，仅作文笔/结构参照）

橙光制作工具本质是"可视化数值+条件分歧脚本引擎"，西幻分类下作品普遍采用"大陆多国+魔法学院+阵营对立"设定骨架，用"职业分支"映射玩家选择，好感度作为阵营与结局的隐性变量。易次元走"零代码画布模式"，头部作品代表"高自由度养成+多结局"结构。

**对本项目的参照价值不在架构，而在"变量→阵营→结局"的因果设计与西幻品类叙事套路**。中文修仙/武侠文游的冷锻文风（短句、动词密集、名词具象、意象同源）可作 V66 古典白描的风格印证。

#### UPG-01｜设定词系统升级：关键词触发式世界书（Lorebook）

- **优先级**：P0｜**工作量**：中（约 2-3 个批次）

#### UPG-02｜记忆注入 v3：双层加权检索

- **优先级**：P0｜**工作量**：中（约 2 个批次）

#### UPG-05｜回退系统：historyStack + block_rollback

- **优先级**：P1｜**工作量**：中（约 2 个批次）
- **目标**：借鉴 Ren'Py rollback，增加限长节点回退功能，玩家可"回到上一个选择"；对死亡/背叛等不可逆事件阻断回退。
- **范围**：
  - 每次选择前 push `{nodeId, stateDiff, flagsSnapshot, ledgerSnapshot}` 到 `historyStack`（限长 50-100，环形缓冲）。
  - 玩家点"回退"即 pop 并恢复状态。
  - 对不可逆事件（角色死亡、背叛永久化、永久失去物品），在因果账本标记 `irreversible: true`（UPG-03），从该节点起清空 stack——防止玩家刷出最优分支。
  - 修正 SugarCube 的坑：同节点内操作完成后主动刷新 moment，避免回退丢改动。
- **验证方式**：①连续选择 10 次后回退 5 次，断言状态正确恢复；②死亡节点后回退按钮禁用；③historyStack 不超过限长（环形覆盖）；④回退后重新选择不导致存档结构异常。
- **铁律兼容性**：✅ 兼容。historyStack 为运行时内存对象，不入存档（saveVersion=48 不变）；不触碰判定公式。需注意回退可能导致 choose 判定重跑，但判定公式本身不变。
- **对标来源**：Ren'Py rollback 环形缓冲 + block_rollback()、SugarCube moment 栈。

- **目标**：将 elda-content-author + SP-1~SP-8 流水线升级为"生成前注入世界书+GameState → 生成 → 生成后四段式质检 → 反 AI 味六维后处理 → 人味标注"的完整闭环。
- **范围**：
  - **生成前**：节点上下文从"裸文本"改为"结构化 GameState + 命中世界书词条（UPG-01）+ 因果账本 Top-K（UPG-02）+ 上一节点摘要"三段式注入。

#### UPG-14｜事件池全局钩子（Evennia Scripts 模式）

- **优先级**：P2｜**工作量**：中（约 2 个批次）
- **目标**：借鉴 Evennia Scripts/GLOBAL_SCRIPTS，在 176 事件池基础上引入"全局钩子脚本"——不绑定具体节点，挂在游戏主循环上的条件触发器。
- **范围**：
  - 定义全局钩子表：`{id, condition, eventId, cooldown, maxTriggers}`。
  - 每次节点切换后扫描钩子表，condition 满足则触发对应事件池事件。
  - 示例钩子：①玩家声望 < 阈值时触发通缉事件；②每 5 步触发边境冲突检查；③深渊腐蚀度 > 30 时触发深渊裂隙事件；④某势力关系 < -60 时触发敌对势力伏击。
  - 因果账本中"待回收伏笔"可由钩子定期扫描并在合适节点弹出。
- **验证方式**：①钩子条件满足时事件正确触发；②cooldown/maxTriggers 生效（不会每节点都触发）；③不影响现有 176 事件的正常触发；④elda ci 增加"钩子 condition 引用的变量已声明"校验。
- **铁律兼容性**：✅ 兼容。事件池只增，不改核心；钩子在节点切换后扫描，不触碰 writeNext/choose 判定公式。需注意钩子触发的事件仍走现有事件池逻辑。
- **对标来源**：Evennia Scripts（可持久化/可定时/可重启恢复的回调对象）+ GLOBAL_SCRIPTS。

## 七、风险与注意事项

1. **UPG-15 节点物理分区风险最高**：涉及构建链调整，必须保持四路字节一致（game=game_check、chunked=index），建议渐进式迁移，每次一个区域，全量回归后再继续。
2. **UPG-05 回退系统需谨慎处理 choose 判定重跑**：回退后重新选择可能导致随机数/判定结果不同，需明确"回退=回到选择前状态重新选择"而非"撤销选择"。
3. **UPG-01/02 设定注入升级需 A/B 验证**：全量常驻→关键词触发可能导致某些场景设定注入不足，需在升级后跑全量回归+人工抽检，确保"不能遗忘设定"（金秤/晨天/七锚/铁牌/神谕）。
4. **所有批次必须遵守铁律**：saveVersion=48 不变、节点只增不降、不触碰判定公式/writeNext/choose、改动前备份 backup\、V66 文风+30 治理词+中文引号成对+战斗四段式。
5. **P2 内容级批次（UPG-16）工作量大**：种族/职业/魔法深化涉及大量内容创作，建议与其他批次穿插进行，避免阻塞工程化升级。
